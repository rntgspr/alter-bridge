# T1 — Builder `go/release.sh` and launcher

## What to do

- `go/release.sh`: cross-compile `./cmd/alter-bridge` with `CGO_ENABLED=0` for
  each target into `go/alter-bridge-<os>-<arch>`. Then write
  `dist/alter-bridge-<version>.zip` containing `.claude-plugin/plugin.json`,
  `hooks/hooks.json`, `skills/`, the `go/` binaries, and the launcher. Also
  print the zip's `sha256`.
- `go/alter-bridge`: a POSIX `sh` launcher. It maps `uname -s` and `uname -m`
  to `<os>-<arch>` and `exec`s the matching binary with `"$@"`. If there is no
  match, it prints one line to stderr and exits 0.
- `.gitignore`: ignore the built `go/alter-bridge-*` binaries and `dist/`.

## Context

- The binaries land in `go/` (Renato's decision).
- The existing `go/build.sh` and `bin/alter-bridge` stay as they are, because
  Codex and local dev still use them.
- Targets: darwin-arm64, darwin-amd64, linux-amd64, linux-arm64 (assumed, see
  the plan's Risks).

## Implementation

1. Write a failing test first: a shell test that runs the launcher with a fake
   `uname` on `PATH` against stub binaries, covering both a match and a miss.
2. Implement the launcher, then `release.sh`.

## Done when

- [ ] Launcher test is green for darwin-arm64, linux-amd64, and an unknown
  arch (exit 0, stderr notice).
- [ ] `go/release.sh` builds all targets and prints a zip + sha256; `unzip -l`
  shows the AC1 layout.
- [ ] `go test ./...` in `go/` still green.
