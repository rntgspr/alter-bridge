# T2 — `relay` subcommand

## What to do

```
alter-bridge relay provider[:value] < payload.json
```

- `relay.go`: `relayUsage`, `relayEnv` (Root, Resolver, Stdin, Stdout,
  Stderr, `Ring func(name, prompt string) error`, `Nudger nudge.Nudger`),
  `runRelay(args, relayEnv) int`:
  - argument check and `hookAddress` exactly as `watchpaths` (exit 2);
  - read stdin, append `time.Now().UTC() 15:04:05 + " " + payload` (trailing
    newlines trimmed) to `<root>/.tmp/relay.log` (`O_APPEND|O_CREATE`,
    errors ignored);
  - decode; `event == "add"`, `file_path` under `root/`, session id for a bare
    provider, `Resolver.Slug` (error → exit 1), `filepath.Dir(file_path) ==
    root/provider/slug`, basename `*__from_*__*.md`;
  - sender / msgid / notice as bash; ring: `claude` → `Ring("relay-"+Slugify(sender), prompt)`,
    `codex` → `Nudger.Notify(sender address, provider:slug, msgid)`;
  - `{"systemMessage": notice}` through `json.Encoder`, HTML escaping off.
- `main.go`: `relay` case with `broker.Resolve`, `session.NewResolver`,
  `Ring` bound to `nudge.RingClaude(session.ClaudeBin(home), home, ...)`,
  `Nudger` as in `send`, and a usage line.

## Context

Bash `relay()` (`alter-bridge:333-397`); see the plan Overview for identity
and the per-provider ring.

## Implementation

1. Tests first (in-process, temp root, fake stores, recording `Ring` and
   `Nudger.Run`): own `add` prints the exact line and rings with the exact
   name/prompt; `change`, foreign mailbox, outside root, non-message basename,
   empty payload, and bare provider without id are silent; log line appended
   in every valid call, never creating `.tmp`; codex nudges instead of
   ringing; HTML characters unescaped; usage errors exit 2 without logging;
   ambiguous name exits 1.
2. Watch them fail, implement and wire.
