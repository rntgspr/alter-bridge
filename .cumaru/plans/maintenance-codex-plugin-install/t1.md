# T1 - Inventory and prepare Codex installation

## What to do

Inspect the current Codex marketplace, installed plugins, hook definitions,
trust state, and local plugin files. Identify only the Codex entries that the
cutover will change. Back up every affected global file with a timestamp
before mutation, and build the local binary expected by the Codex plugin.

## Context

`maintenance-plugin-standard` T1 and T2 prepared the local Codex plugin.
Codex copies local plugin contents into its cache, so the build must precede
installation. Keep the Claude-side release work in its separate thread.

## Implementation

1. Record the current `codex plugin` and hook state, including the legacy
   plugin, manual hook, and any unrelated entries that must be preserved.
2. Verify `.codex-plugin/plugin.json`, `hooks/codex.json`, marketplace source,
   and `bin/alter-bridge` build path against the current Codex CLI.
3. Save timestamped copies of each Codex global file that T2 will mutate.
4. Build the binary and record the commands and outputs in the handoff.

## Done when

- [ ] The current Codex registrations and affected files are documented.
- [ ] Every affected existing global file has a timestamped backup.
- [ ] The local binary builds and runs before plugin installation.
