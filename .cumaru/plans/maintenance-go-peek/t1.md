# T1 — `peek` CLI wiring on a shared drain runner

## What to do

```
alter-bridge peek <provider:value>
```

- Extract the body of `runInbox` into `runDrain(args, env inboxEnv, archive bool, usage string) int`; `runInbox` becomes `runDrain(args, env, true, inboxUsage)`.
- Add `peek.go` with `peekUsage` and `runPeek` = `runDrain(args, env, false, peekUsage)`.
- Add the `peek` dispatch case and usage line in `main.go`, using the existing `setup()`.
- Exit codes as `inbox`: 0 ok (including empty/missing mailbox), 2 usage, 1 refusal or filesystem error.

## Context

Bash reference: `peek() { drain no "$@"; }` (`alter-bridge:273`). `mailbox.Drain(root, box, false, w)` already never moves files (`maintenance-go-inbox` T1). The Go identity model forbids an environment fallback for the address.

## Implementation

1. Tests first (`peek_test.go`, in-process, temp root, fake stores): two messages print oldest first in inbox format and stay pending, no `.archive/`; id resolves to the name mailbox; empty mailbox exits 0 silently; refusals (missing, `-h`, extra, malformed, unknown provider → 2; ambiguous, empty slug → 1) print nothing.
2. Watch them fail (undefined `runPeek`), then extract `runDrain` and add `runPeek`; existing `inbox_test.go` must stay green.
3. Wire the dispatch case.
