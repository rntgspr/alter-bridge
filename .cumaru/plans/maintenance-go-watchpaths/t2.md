# T2 — `watchpaths` subcommand: payload, gate, mkdir, watchPaths JSON

## What to do

```
alter-bridge watchpaths provider[:value] < payload.json
```

- `watchpaths.go`: `watchpathsUsage` and `runWatchpaths(args, hookEnv) int`
  (same env as `hook`).
  - Exactly one argument; `-h`/`--help`, none, or extra → usage, exit 2;
    `hookAddress` error → stderr, exit 2.
  - `hookSession`; outside the workspace → exit 0, silent. Bare provider
    with no session id → exit 0, silent.
  - `Resolver.Slug`; `os.MkdirAll` of `<root>/<provider>/<slug>` and
    `<root>/.tmp`; errors → stderr, exit 1.
  - Encode `{"hookSpecificOutput":{"hookEventName":"SessionStart","watchPaths":[dir, dir/slug]}}`
    with `json.Encoder`, HTML escaping off, so the line matches `jq -nc`.
- `main.go`: `watchpaths` case with `broker.Resolve` (the root is created
  only after the gate, by the `MkdirAll`, as bash does), `session.NewResolver`,
  `os.Getwd`, and a usage line.

## Context

Bash `watchpaths()` (`alter-bridge:300`). Identity and gate follow `hook`
(see the plan's Overview). `setup()`/`EnsureRoot` would create the root before
the gate, which bash never does outside the workspace.

## Implementation

1. Tests first (in-process, temp root, fake stores): bare provider registers
   the session-name mailbox from each id key, creating it and `.tmp`; exact
   stdout bytes; explicit address ignores the payload id; outside-workspace
   and unusable payloads are silent and create no root; usage errors exit 2
   and create nothing; ambiguous name and an uncreatable directory exit 1.
2. Watch them fail (undefined `runWatchpaths`), then implement and wire.
