# T2 — Session lookup by id per provider

## What to do

Create `internal/session` exposing `Slug(provider, value string) (string, error)`:

- `value` is a session id in the provider's store → slugified session name, or slugified id when the name is empty.
- Otherwise `value` is a name → collect **active** sessions whose slugified name equals `Slugify(value)`:
  - 0 or 1 match → return the slug.
  - 2+ matches → return an `AmbiguousError` carrying the candidate ids.
- Store unavailable or read error → slugified `value`, no error.

Per-provider store:

- `claude` — scan `~/.claude/projects/*/*.jsonl` for `"type":"custom-title"` entries; the file name is the session id, the latest `customTitle` per session is its name. No archive flag: every titled session is active.
- `codex` — `threads` in `~/.codex/state_5.sqlite` (`id`, `name`, `archived`); active = `archived = 0`. Fallback `~/.codex/session_index.jsonl` (`id`, `thread_name`), all treated as active.
- `opencode` — `session` in `~/.local/share/opencode/opencode.db` (`id`, `title` or `slug`, `time_archived`); active = `time_archived IS NULL`. Confirm the human-facing name field first.

Also expose the reverse lookup T5 needs: `CodexThreadForSlug(slug string) string`, active threads only.

## Context

Bash reference: `claude_session_name`, `codex_session_name`, `codex_thread_for_slug` (`alter-bridge:47-124`). Bash's Claude lookup uses `claude agents --json`, which failed on v2.1.280 and only lists background agents — do not port it. No environment variable decides identity; `$HOME` only locates the stores. Open SQLite stores read-only (`mode=ro`). Observed collision evidence: 9 OpenCode sessions share one auto title, so the ambiguity path is not hypothetical.

## Implementation

1. Decide SQLite access: shell out to `sqlite3` (bash parity, no dependency) vs a pure-Go driver. Prefer `sqlite3`; record the choice in the handoff.
2. Confirm OpenCode's name field against a real `opencode.db` with a renamed session.
3. Put store reads behind small injectable functions so tests use fixtures (temp sqlite db, temp jsonl dir), not live CLIs.
4. Tests first: id with name; id without name; unknown name (0 matches); one active match; archived match ignored; two active matches → `AmbiguousError` with both ids; store missing; Claude title renamed twice (latest wins).
